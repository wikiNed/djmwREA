# 《点击魔王》逆向分析报告

> 目标：TapTap 版《点击魔王（TapTap测试版）》v5.9.2
> 目的：单机数值/存档修改
> 分析时间：2026-10-28
> 分析环境：Windows，REA 6.8.0 + UnityPy 1.25.4 + Python 3.12

---

## 零、结论先行

**这个游戏是逆向难度最低的一档，几乎没有任何防护。**

| 维度 | 结论 |
|---|---|
| 引擎 | Unity 2022.3.62f2c1 + IL2CPP（arm64 / armeabi-v7a 双架构） |
| 代码保护 | **无**。`global-metadata.dat` 未加密，版本 31，类名/字段名明文可读 |
| 存档格式 | **纯明文 JSON**，多段用 `$` 拼接，**无加密、无签名、无校验** |
| 数值表 | 明文 JSON（TextAsset 内置） |
| 加固/反调试 | 只针对**广告 SDK**（字节、腾讯、穿山甲），游戏本体无保护 |
| 修改可行性 | **极高**。改存档只需文本编辑器级别操作 |

一句话：**不需要脱壳、不需要 IL2CPP dump、不需要动态调试。** 直接改存档就能改数值。

## 三、存档格式（核心发现，observed）

### 3.1 结构

存档 = **多个独立 JSON 对象用 `$` 字符拼接成的一个字符串**。

```
{段0}${段1}${段2}$...${段13}
```

- 每段自带 `DateID` 字段标识段号（0~13）
- **无 BOM、无加密、无压缩、无 HMAC、无 CRC**
- 实测 `json.loads` 在 `$` 处报 `Extra data`，正确拆法是 `split('$')`

## 四、逆向方案

### 4.1 路线选择

针对「改数值/存档」，有四种手段，**按推荐度排序**：

| 方案 | 难度 | 持久性 | 推荐度 |
|---|---|---|---|
| **A. 直接改存档文件** | ★☆☆☆☆ | 高 | ⭐⭐⭐⭐⭐ |
| **B. 改 APK 内置演示存档** | ★☆☆☆☆ | 中（重装失效） | ⭐⭐⭐ |
| **C. IL2CPP 打补丁改逻辑** | ★★★★☆ | 高 | ⭐⭐ |
| **D. 运行时内存修改** | ★★☆☆☆ | 低（每次重来） | ⭐ |

**先把 A 做透，再考虑 C。B 和 D 只在 A 不可行时才用。**

---

### 4.2 方案 A：直接改存档文件（首选）

#### 前提：找到真实存档路径

数据里 `playerDate_0N` 出现在 `assets/bin/Data`（TextAsset），这是**出厂演示存档**。
真实运行时的存档位置需要动态确认，候选顺序：

1. `Application.persistentDataPath` —— Android 上即
   `/data/data/game.taptap.HQGAMES.TapDemons/files/`
2. `PlayerPrefs` —— `/data/data/.../shared_prefs/*.xml`
3. 外部存储 —— `/sdcard/Android/data/game.taptap.HQGAMES.TapDemons/`

> Android 11+ 对 `/sdcard/Android/data` 有访问限制，**优先走 root 或 adb 的 app 私有目录**。

**确认手段（按信号强度）：**
- `adb shell run-as game.taptap.HQGAMES.TapDemons ls files`（debuggable 才有效）
- root 直接 `ls -la /data/data/game.taptap.HQGAMES.TapDemons/`
- 或先玩一局，再用 `find / -name "*playerDate*"`

#### 修改步骤

```
1. 备份原存档（必须，改坏了要能回滚）
2. adb pull / 复制到电脑
3. 文本编辑器打开
4. 按 '$' 分段，定位目标段（段号看 DateID）
5. 改数值字段
6. 写回，注意：
   - 保持 UTF-8 无 BOM
   - 不要改分隔符 '$'
   - 不要破坏 JSON 结构（引号/逗号/括号）
   - long 字段不要超 2^63-1
7. 改文件属主/权限为应用用户（root 下 chown/chmod）
8. 启动游戏验证
```

#### 高风险点（必须先想清楚）

1. **演示存档 ≠ 真实存档**。段结构很可能一致，但字段可能随版本增删。改之前先对比自己的存档和内置样本的差异。
2. **可能有隐式互检**。比如 `TapLevel` 与 `TapZongShu`（点击总数）如果互相约束，只改等级不改总点击数可能被重算覆盖。→ **改守恒量一致的一对数**，别只改一个。
3. **可能通过 `JiaMi` 类对某些段做二次处理**。类名存在但未必被调用——**先做一次「不改内容、只把 JSON 重新序列化再存回」的实验**：如果游戏能正常读，说明无签名字段；如果报错/回档，说明有校验。
   > 这是最省时间的判定法，强烈建议第一步做这个。

4. **`IsJiHuo`/`IsHuangJin`/`GuoQiTime` 是付费字段**。改这些等于伪造付费，法律与账号风险高于改单机数值，**建议不动**。

---

### 4.3 方案 B：改 APK 内置演示存档

`assets/bin/Data/data.unity3d` 里打包了 `playerDate_01/02/03` 三个演示存档。

- 用 **UnityPy** 打开 `.apk` 直接读取（本次已验证可行）
- 但**回写**需要重新打包 Unity 资源：
  1. UnityPy 修改 TextAsset 的 `m_Script` → `obj.save()`
  2. 重新压缩 APK（保持 `zipalign` + `apksigner` 签名）
  3. 卸载原版重装（**签名不同无法覆盖安装**）

> 注意：本次解析中 `data.unity3d` 的 **UnityFS 头部不标准**（目录流不是标准排列，官方工具与自写解析器都失败），**只能靠 UnityPy 这种容错解析器读**。回写风险较高，因为 UnityPy 重打包可能改变布局。**如果 A 能跑通，不建议走 B。**

---

### 4.4 方案 C：IL2CPP 补丁（改逻辑而非改数据）

适用场景：想改的是**计算规则**（比如收益倍率），而不是想改某个具体数字。

#### 步骤

```
1. 从 APK 提取：
   - lib/arm64-v8a/libil2cpp.so
   - assets/bin/Data/Managed/Metadata/global-metadata.dat
2. Il2CppDumper（或 Zygisk-Il2CppDumper）生成 dump.cs
3. 在 dump.cs 里搜：SaveManager / PlayerDataModel / ReadJsondata / ShuJuQuanKai / JiaMi
4. 找到目标方法的 RVA
5. 用 IDA/Ghidra 载入 libil2cpp.so（基址 0），跳到 RVA 处
6. 定位 ARM64 指令，做补丁：
   - 返回常量：把函数体改成 `MOV W0, #常量; RET`
   - 跳过校验：把条件跳转改成无条件跳转 或 NOP
7. 用 LIEF / 十六进制编辑写回 so（注意保持 ELF 结构）
8. 重新签名 APK 并安装
```

#### 环境要求（本机目前不具备）

| 需要 | 状态 |
|---|---|
| JDK 21+（跑 Ghidra / Il2CppDumper 的辅助工具） | ❌ 未安装 |
| Ghidra 或 IDA | ❌ 未安装 |
| Il2CppDumper | ❌ 未获取 |
| 一台 root 的 Android 设备/模拟器 | 未知 |

> 本次分析是在**无 Java、无 Ghidra** 的条件下完成的——这恰恰说明 **A 方案完全不依赖重武器**。

#### 关键类优先级

如果在 dump.cs 里翻代码，按这个顺序看：

1. `SaveManager` —— 读写存档的方法，看有没有额外处理
2. `ReadJsondata` —— JSON 解析，看有没有字段白名单
3. `PlayerDataModel` —— 字段定义与默认值
4. `JiaMi` —— 加密工具，**确认它到底被谁调用**（很可能只给广告 SDK 用）
5. `ShuJuQuanKai` —— 「数据全开」，如果存在可调用的开关，可能直接一键解锁
6. `CeShiDate` —— 测试数据，可能有调试入口

---

### 4.5 方案 D：运行时内存修改

工具：Frida / GameGuardian / 内存搜索器。

思路：钻石 `ZuanShi` 是 4 字节 int，直接搜值改值。但——

- 需要在真机/模拟器上跑
- 游戏有 IL2CPP，类型信息可辅助搜索
- **每次启动都要重做**，且大概率触发游戏自身的数值重算

**只建议当 A/C 都失败时的兜底。**

## 五、风险与边界

### 5.1 技术风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 存档有隐藏校验 | 可能存在未在明文里暴露的 hash 字段 | 先做「无损重存回」实验 |
| 字段互相约束 | 改 A 被 B 覆盖 | 成对改守恒量 |
| 版本升级覆盖 | 更新后格式变化 | 保留原版 APK 与本报告 |
| APK 重签名后掉登录态 | TapTap SDK 校验签名 | 方案 A 不动 APK，规避此问题 |

### 5.2 非技术边界

- **本项目是单机游戏，改存档不影响其他玩家**，这是主要的安全垫。
- **但 `IsHuangJin`/`IsJiHuo`/`NeiGouCiShu` 涉及付费状态**，改动属于伪造内购，建议**完全避开**。
- 存档里含 `ZhangHao`（明文邮箱）、`WeiYiMa`、设备信息 —— **不要把改过的存档样本公开发布**。
- `libthemis.so` 是腾讯的隐私合规 SDK，不是反作弊。但 TapTap SDK 会**上报设备指纹**，修改行为在统计上可见。

## 六、可执行的下一步

按顺序做，每步都有明确的成功/失败信号：

### Step 1：判定有无校验（10 分钟）
```
目标：确定存档是否「原样重存就能读」
做法：不改任何值，把 playerDate JSON 用脚本解析→重新 dump→写回
信号：游戏能正常进档 → 无校验，方案 A 畅通
      游戏报错/回档/清档 → 有校验，转 Step 4
```

### Step 2：定位真实存档路径
```
目标：拿到运行时真正的存档文件
做法：adb run-as / root ls / 一次性 find
信号：找到含 playerDate 或 .es3 的文件
```

### Step 3：改一个低风险字段验证闭环
```
目标：证明「改 → 存 → 生效」链路通
建议：先改 MuCaiShuLiang（木材，段2），影响面小
信号：进游戏木材数值变化，且不被回收
```

### Step 4（仅在 Step 1 失败时）：进入 IL2CPP
```
目标：找到校验逻辑并绕过/复现
前置：装 JDK 21 + Il2CppDumper + Ghidra
入口：SaveManager / ReadJsondata / JiaMi
```
