# 33 · 魔窟（MoShiKu）补丁：体力 / 商店 / 魔石 / 魔物碎片

> v14 → v19，真机（Huawei P30，Android 10，arm64-v8a）验证通过。

## 1. 需求与结论

| # | 需求 | 结论 |
|---|---|---|
| 1 | 进魔窟不消耗体力 | `RemoveTiLi` 直接 `ret`；`MaoXian` 里的 `bl AddTiLi` 也 NOP |
| 2 | 魔窟商店买东西不扣资源 | 8 个购买分支里的 `bl RemoveZuanShi` / `bl RemoveMoWuSuiPian` 全部 NOP |
| 3 | 魔石数量 99999999 | 加载点改成从 .rodata 常量池 `ldr` 一个 int64 |
| 4 | 魔物碎片恒 1000 | 加载点写常量；`RemoveMoWuSuiPian` 内部写回 1000 |
| 5 | 商店库存不减少 | 8 处 `add w8,w8,#1` → NOP |

### 关键函数

| RVA | 名字 | 说明 |
|---|---|---|
| `0x8C7278` | `RemoveTiLi` | 唯一调用者是 `GouMaiTiLi`（买体力） |
| `0x8C7AB8` | `MaoXian` | 进洞路径，里面反而 `bl AddTiLi` |
| `0x8C8728` | `GouMaiShangPin` | 商店购买总分派 |
| `0x8C8600` | `IsBuy` | **只做余额比较**，不扣钱 |
| `0x8C7B7C` | `LoadMoShiKuManager` | 存档 → 缓存的同步点 |
| `0x8C60C8` | `RemoveMoWuSuiPian` | 扣魔物碎片 |

### `IsBuy` 的真面目（0x8C8600）

```
0x8C8630  ldr w8,[x19,#0x38]        ; xiaoHaoLeiXing
0x8C8634  cmp w8,#4 / b.eq 0x8C86C4 ; 魔物碎片 → Date_MoShiKu+0x60
0x8C863C  cmp w8,#1 / b.eq 0x8C8684 ; 魔石     → Date_MoShiKu+0x58
0x8C8644  cbnz w8,0x8C8714          ; 其它 → return false
0x8C8700  ldr x8,[x8]               ; 余额
0x8C8708  cmp x8,x9                 ; 比价格
0x8C8710  b 0x8C8718                 ; 返回 x8 >= 价格
```

**它读的是存档字段，不是管理器缓存** —— 所以把缓存写成 1000 只会让界面显示 1000，
判余额时仍是存档里的真实值。

### 3.5 魔石 = 99999999（本次新增）

`0x8C7DB8` 只有**一格**空位，而 99999999 = `0x05F5E0FF` 需要 `movz` + `movk` 两条，
写不进去。于是改用 **.rodata 常量池 + `ldr` 字面量**：

| 位置 | 内容 |
|---|---|
| `0x847BE0` | 写入 int64 `99999999`（该处是 .text 段内 4076 字节全零填充，无任何引用） |
| `0x8C7DB8` | `52807D09` → `58BFF149`（`ldr x9,[pc,#-0x801D8]` → 0x847BE0） |
| `0x8C7DBC` | `F9002E69`（`str x9,[x19,#0x58]`，原样保留） |

`LDR (literal)` 编码：`0x58000000 | (imm19<<5) | Rt`，目标 = `PC + imm19*4`；
`0x847BE0` 距 `0x8C7DB8` 约 377 KB，在 ±1 MB 范围内。

脚本 `scripts/patch_v19_moshi_nine9.py` 自带三重断言（原值必须匹配、填充区必须全零）。

## 5. 踩过的坑

1. **每函数只 NOP 第一处**：`GouMaiShangPin` 有 8 个分支，v14 只堵了 2 个，
   用户实测「还是消耗」——改一个分支不代表堵住全部，必须扫全函数所有 BL。
2. **字段 ≠ getter**：改 `get_MoWuSuiPianShuLiang @0x8C5630` 没用，
   界面直读管理器字段 `+0x60`。这是 IL2CPP 项目的通用陷阱（v12 的欧气同款）。
3. **v16 的 `mov w8,#0` 是错的**：后面紧接 `str x8,[x19,#0x60]`，
   会把碎片写成 **0** 而不是 1000。
4. **`IsBuy` 读存档、不读缓存**：显示 1000 但判余额用存档里的 3，
   碎片标价商品仍会「余额不足」。彻底解决需要改 `0x8C8700` 的读取。
5. **push 存档前必须 `am force-stop`**，否则游戏用内存旧值覆盖回文件。
6. **adb 掉线**：`adb kill-server` + `start-server` 后重新识别设备。
