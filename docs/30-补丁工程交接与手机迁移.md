## 3. 补丁清单（当前 = v17，`scripts/build_patched_apk.py`）

> 全部是 ARM32 指令，`file_offset == RVA`。脚本会**逐条断言原值**，任何一条对不上就退出，不会产出半成品包。

### 3.1 反作弊豁免（8 处，核心）

| RVA | 原值 → 新值 | 含义 |
|---|---|---|
| `0x3D0F10` | E92D4830 → E12FFF1E | `ZuoBi.Start` → `bx lr`：封号场景的协程永不启动 |
| `0xE8EBC0` | EBD86EE5 → E1A00000 | ZuoBi 协程内 `PlayerPrefs.DeleteAll` → nop |
| `0xE8EC18` | EBE5965C → E1A00000 | ZuoBi 协程内 `ChongWuPool.DeleteSave` → nop |
| `0x3EE4CC` | EB029CC2 → E1A00000 | `FengHaoUI.SetActive(true)` → nop |
| `0x7BDEF8` | E92D4C10 → E12FFF1E | `ShuJuDate.QingDang` → `bx lr`：**永不删档** |
| `0x3EE4A0` | 0A000061 → EA000061 | 黑名单判定 `beq`→`b`：永远跳过封号分支 |
| `0x3EDB48` | EB0ADC50 → E1A00000 | `GetBaoName` 里的 `LoadScene(Level_ZuoBi)` → nop |
| `0x7B89C4` | EBFBB0B1 → E1A00000 | `ShengMingZhiShuUI` 37 天闸 → `LoadScene(Level_ZuoBi)` nop |

封号链路原本只有 3 个 `QingDang` 调用点：`0x3EE518`、`0x3EF1D0`（两个 `XianShiNiCheng` 协程）、
`0xE8EBB8`（ZuoBi 场景协程）。`PlayerPrefs.DeleteAll` 与 `ChongWuPool.DeleteSave` 只在 `0xE8EBC0/E8EC18`。
把这 8 处全堵上之后，**实测再触发检测也不会掉档、不掉 prefs**（红屏可能仍出现一瞬间，重启即可）。

### 3.2 宝石洞穴次数（3 处）

| RVA | 原值 → 新值 | 含义 |
|---|---|---|
| `0x68F9F0` | E92D4830 → E12FFF1E | `ShenQiBaoShiDateModel.AddBaoShiDongTiLi` → `bx lr`（模型侧已用次数不增） |
| `0xED0B98` | E2800001 → E1A00000 | `DiXiaChengUIManager` 里 `[r4+0x14]` 自增 → nop（界面侧次数不增） |
| `0xED0428` | AA00003C → E1A00000 | `SuiJiBaoShi` 的 `已用 >= Max` 闸门 `bge` → nop |

**两处计数都要冻**：模型侧（ES2 存档 `DangQianTiLi`）和界面管理器侧（`[uimgr+0x14]`）是两份独立计数。
只冻模型侧时，界面侧挖 30 次仍会撞上限 60 而停摆 —— 这是踩过的坑。

**上限必须保持原值 60**：把 `get_BaoShiDongTiLiMax` 改成 999/999999 会在挖几次后触发检测
（已用=30 时 999 ⇒ 剩余 969 > 60，被判定异常）。安全区：`1 ≤ 已用 ≤ 59` 且 `Max = 60`。

### 3.3 远古宝石概率 30%（2 处 + 1 段打桩）

| 位置 | 内容 |
|---|---|
| `0x690944` | 00000000 → 3EDB6DB7（= 3/7 = 0.42857143f） |
| `0x7EC2BC` | `get_YuanGuBaoShiUp` 4 字打桩：`movw r0,#0x6DB7; movt r0,#0x3EDB; vmov s0,r0; bx lr` |

掷骰公式（`RandomXiYouDu @ 0x690598`）：

```
T = 1.0 + get_ChuanShuoBaoShiUp() + get_YuanGuBaoShiUp()
r = Random.Range(0, T)
七层权重里 PT+JZ+XY+SS+CS 每层恰好 = 1.0
r >= 1.0 才返回「远古」
⇒ P(远古) = (CSup + YGup) / (1 + CSup + YGup)
```

原版 YGup ≡ 0 ⇒ 远古区间宽度为 0 ⇒ **数学上永远挖不到**（这就是「挖了 120 次没有远古」的原因）。
取 YGup = 3/7 ⇒ P = 0.3。**实测 60 次挖宝：总 212 颗、远古 20 颗 = 33.3%**，与设计吻合。

> 注意：`0x6904E8` 那个常量池**不是**主路径（只写进 `[r4+0x1c]`），改它无效 —— 早期版本踩过。

### 3.4 进层衰减（1 处）

| RVA | 原值 → 新值 | 含义 |
|---|---|---|
| `0xED02BC` | BDCCCCCD → BC23D70A | `nextCengGaiLv = 0.9 - 层×0.1` 里的 **-0.1f → -0.01f** |

### 3.5 木材/矿石产量 ×889（4 处）

`get_FaMuChangChanNeng @ 0x7AE71C` / `get_KuangShiChangChanNeng @ 0x7AF498`：
`ChanNeng = 等级 × 1`（有 buff 时 ×2）。把两处 `mov r1,#1` / `movweq r1,#1` 改成 `movw r1,#889`：

| RVA | 原值 → 新值 |
|---|---|
| `0x7AE764` | E3A01002 → E3001379（wood buff） |
| `0x7AE77C` | 03001001 → 03001379（wood normal） |
| `0x7AF4E0` | E3A01002 → E3001379（ore buff） |
| `0x7AF4F8` | 03001001 → 03001379（ore normal） |

实测原速率 ≈ 11.25/s（伐木场 299 级），×889 ⇒ ≈ 10000/s。

### 3.6 分解碎片 ×100（单颗 1 处 + 一键 6 处）

原逻辑都是「`JiSuanSuiPian()` 结果 ÷ 2」（`pmull` 风格：`lsrs r1,r1,#1; rrx r0,r0`）。
把这段改成 `raw × 50` ⇒ 相对原版净 **×100**。

单颗分解 `GetFenJieSuiPianShu @ 0x69192C`：

| RVA | 原值 → 新值 |
|---|---|
| `0x691938` | E1B020A1 → E3A02032（mov r2,#50） |
| `0x69193C` | E1A00060 → E0810290（umull r0,r1,r0,r2） |
| `0x691940` | E1901002 → E8BD8800（pop {fp,pc}） |
| `0x691944` / `0x691948` | → nop |

一键分解 `GetYiJianFenJieShu @ 0x6919A0` **不用**上面那个函数，它在 `0x691B9C` 直接调 `JiSuanSuiPian`，
而且**六种颜色（红/绿/蓝/黄/紫/玉）各有一份内联副本**，偏移：

```
0x691BA0  0x691E70  0x69213C  0x692408  0x6926D4  0x6929B4
```

每处都是 5 条指令，统一替换成：

```
mov r2, #50          ; E3A02032
umull r0, r1, r0, r2 ; E0810290
mov r2, r1           ; E1A02001
nop                  ; E1A00000
nop                  ; E1A00000
```

只改一处 ⇒ **只有红宝石一键分解翻倍**，其它颜色不变 —— 这是用户实测发现的（已修）。

## 5. 存档

- 路径：`/storage/emulated/0/Android/data/com.HQGAMES.TopDemons/files/<账号>`
- 格式：`header(14B) + hex_upper(DES-CBC-PKCS7(明文)) + "{"`
  - key = iv = `PJSQJ678`，框架是 Easy Save 2
  - 14 段以 `$` 分隔，段名顺序见 `docs/23`
- **header 由 ES2 自己写**，算法已完全解出（varint 长度），见 `scripts/v557save.py`
  的 `make_header()` / `predict_header()`，7 份原生档逐字节复现。

推送（**必须游戏已 stopped**，否则会被内存旧值覆盖）：

```bash
adb push x.save /data/local/tmp/x.save
adb shell "su 0 mkdir -p <dir> && su 0 cp /data/local/tmp/x.save <dst> \
  && su 0 chown u0_a47:ext_data_rw <dst> && su 0 chmod 660 <dst> \
  && su 0 chcon u:object_r:media_rw_data_file:s0:c45,c256,c512,c768 <dst>"
```

`chcon` 那一步不能省：少了 MLS 类别，游戏读不到档（表现为读档异常 / 空档）。

拉取同理，**必须 `su 0 cp` 到 /sdcard 再 `adb pull`**（PowerShell 的 `>` 重定向会把二进制转成 UTF-16 损坏）。

工具：

| 脚本 | 用途 |
|---|---|
| `scripts/set_cave_used.py <src> <dst> <n>` | 改 seg9 的 `DangQianTiLi`（洞穴已用次数） |
| `scripts/refill_res.py` | 把木材/矿石补满仓 |
| `scripts/v557_goldtree.py` | 激活黄金树（`GuoQiTime = now+30天`，< 37 天闸门） |

## 7. 已验证结论 & 关键坑

**已验证**
- 远古 30%：60 次挖宝 20 颗（33.3%）
- 洞穴次数冻结：连续挖 30+ 次，`DangQianTiLi` 始终停在 30
- 产量 ×889：离线 10 分钟进账 164 亿木（配合满仓）
- 分屏 ×100：两套路径（单颗 / 一键）都已翻倍
- 红屏触发后**存档与 prefs 不再被删**（8 处反作弊补丁生效）

**坑**
- `DangQianTiLi = 0` 载入 ⇒ **秒封**（「没挖过但宝石统计巨大」自相矛盾）→ 安全区 1..59
- `Max` 改大 ⇒ 挖几次就封 → 必须保持 60
- 只冻模型侧计数 ⇒ 挖 30 次后界面侧撞上限停摆 → 界面侧自增也要 nop
- 一键分解与单颗分解是两套代码，且一键分解**按颜色复制了 6 份** → 改一处只对一种颜色生效
- push 存档必须在游戏 stopped 状态
- `chcon` 的 MLS 类别不能少
- 拉二进制不能用 PowerShell `>` 重定向
- BACK 键在 Unity 里会弹「确定要退出游戏吗」，别拿它当「关闭面板」用
- 截图恒 46500 字节 = 僵尸态，不是游戏卡死（也可能是渲染滞后，盲点仍能推进 UI）

## 8. 手机迁移方案（未完成）

**约束**：目标手机**未 root**；用户希望**桩服务跑在手机上**（即不依赖 PC）。

游戏启动就会请求 `time.asp`、`XT_GetGuangBoXinXi.asp`、`qingQiu.asp` 等，
**没有桩服务就卡在登录页**（已实测：无 hosts、无服务 ⇒ 登录请求失败，停在登录页）。

三条路：

### 方案 A：手机本地桩服务（用户首选，但需要 Termux）
1. 把 `global-metadata.dat` 里所有 `http://game.hqgames2013.com/...` 字面量改写成
   `http://127.0.0.1:8080/...`（字符串是 ASCII、独立字面量，可直接原地改写 + 补 `\0`，
   元数据按「起始偏移」索引，缩短不影响其它串）
2. 手机装 Termux（F-Droid 版），`pkg install python`，跑改端口后的 `stub_server.py`（8080 不需要 root）
3. 装 APK，首次登录照常输入账号/密码/验证码
- 优点：完全离线、不依赖 PC
- 缺点：要装 Termux + 会写脚本；Termux 首次装包需要联网

### 方案 B：PC 桩服务 + 局域网 IP（最省事，推荐）
1. 同样改写字面量，但目标改成 PC 的局域网 IP，例如 `http://192.168.88.29/...`
2. PC 上跑 `stub_server.py`（80 端口），打包成 exe 双击即可
3. APK 装上直接用，手机与 PC 同一 Wi-Fi
- 优点：不用 root、不用 Termux、不用改登录逻辑
- 缺点：每次玩要开 PC

### 方案 C：彻底离线（把登录判定 patch 掉）——**尝试过，失败，需重新定位**
- 试过在 `<GetYongHuQingQiu>d__19.MoveNext @ 0x3DB304` 上强跳 `0x3DB96C`（hash 分发改成 `b`），
  并把该分支的 `op_Equality` 改成自比。结果：stub 返回 `111` 时反而提示「账号密码不正确」⇒
  **`0x3DB96C` 不是成功分支**，是失败分支。
- 重新做的正确姿势：先在该函数的 switch 里逐个 case 定位「111 成功」分支
  （可通过 `ComputeStringHash @ 0x328D64` 反算 `"111"` 的 hash 来对照常数），再决定打点。
- 收益最大（手机零依赖），值得做，但需要额外一轮定位。

> 当前模拟器上装的是 **v17（不含登录 patch）**，即方案 A/B 的基础版本；
> 因为方案 A/B 都保留服务器，登录逻辑无需改动。

### 存档迁移
用户选择「新开档」，因此手机端不需要推存档。若要迁移：用 adb 把
`files/nw2026czzqq.com`（当前约 93~107KB）推到同样的路径，`chown u0_aXX` 的 uid 要按新装包的实际 uid 改，
`chcon` 同上，且必须先启动一次游戏让目录创建出来。
