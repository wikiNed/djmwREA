# 18 — 游戏自建账号系统：接口已死，服务端无法注册

> 起点：想在本机「拿到一个能进游戏的账号」，从而跑通「改存档 → 游戏读档」的端到端闭环。
> 结论先说：**接口服务器 `www.hqgames2013.com` 还活着，但账号库已经不存在了。`qingQiu.asp` 对任何输入都不做数据库操作，`qingQiuID=100`（注册）无条件返回 `222`，`qingQiuID=111/222`（登录）一律触发 ASP 运行时错误返回 `?`。无法通过服务器注册或登录任何账号。**

## 二、服务器实测：注册可用，登录已坏

服务器仍在运行：`Microsoft-IIS/8.5` / `ASP.NET`，`Cache-Control: private`，每次请求发 `ASPSESSIONIDQCTDAQRA` cookie。

### 2.1 `yanZhengMa.asp` 返回一个固定的 6 位数字

```
POST /yanZhengMa.asp  body: a=1  ->  b'252409'   （连续 6 次完全一样）
（隔一段时间再测）                ->  b'554355'   （之后又固定为 554355）
```

即验证码**不是一个真正的图形验证码服务**，而是一个带缓存的伪随机值：
- 同一时间窗口内所有 session 拿到的都是同一个码
- 与 cookie / session **无关**（新建 cookie jar 取到的值相同）
- 服务端确实会校验它 —— 传 `000000`、`123456`、`2524091`、`' 252409'`（带前导空格）全部返回 `0`

### 2.2 `qingQiu.asp` 各 mode 的实际行为

所有测试都用 urlencoded（`application/x-www-form-urlencoded`）。**multipart 会被判 `-1`**，说明 ASP 脚本只读 `Request.Form` 的 urlencoded 解析路径。

| 请求 | 实际返回 | 判定 |
|---|---|---|
| 任选 `qingQiuID=100` + 四个字段非空 + 正确验证码 | **`222`** | 无条件成功 |
| `qingQiuID=100` + 验证码错误 | `0` | 验证码被校验 |
| 四个字段中任一为空 | `-1` | 只检查非空 |
| `qingQiuID=111` 或 `222` + 正确账号密码 + 正确验证码 | **`?`** | ASP 未捕获异常 |
| `qingQiuID=111` 无验证码字段 / 空串 | `-1` | |
| `qingQiuID` 枚举 1..130、200..999、9999 | 只有 `100` 返回 `222`，其余全 `?` | |
| `qingQiuID=100` 且 `playerID` 为 SQL 注入载荷 `a'` / `'or'1'='1` / `a'--` | `222` | **不经过数据库** |
| `qingQiuID=100` 同一账号名注册两次、密码不同再注册 | `222` / `222` | 没有唯一性约束 → 无写入 |
| `qingQiuID=100` 同一验证码连用两次 | `222` / `222` | 验证码未消耗 |
| GET `/qingQiu.asp` | `-1` | |

### 2.3 决定性证据

1. **`qingQiu.asp` 的 `200` 响应体只有一个字节**（`Content-Length: 1`），`222` 就是完整响应。
2. `qingQiuID=100` 分支**输入完全不影响输出**：注入载荷、重复账号、复用验证码、任意 `playerID` 长度/字符 —— 全部 `222`。
   → 该分支是「四个字段非空 且 验证码正确 → 打印 `222` → 结束」的**桩代码**，数据库调用已被删除或连接失败后忽略。
3. `qingQiuID=111/222` 分支返回单字符 `?`，这是 ASP/VBScript 在表达式求值失败时最常见的产物（例如 `Response.Write rs("x")` 而 `rs` 为 `Nothing`/`EOF`）。
   → **登录查询代码仍在，但它依赖的账号表已不可用**。

## 三、为什么不能「自己搭一个假的登录服务器」

技术上完全可行（改 APK 的字符串表或在 `/etc/hosts` + 本地 HTTPS 拦截，让 `qingQiu.asp` 回 `222`），但**没有必要**，因为：

1. `DengLuChengGong()` 只是把 `this+0x80` 置 `true`、然后调 `LoadGame()`。它**不需要真实账号**。
2. `LoadGame()` 的失败点是「本地存档文件不存在或 DES 解封失败」—— 两件事我们都已经能完全控制（`es3save.py`）。
3. 真正的门槛是**没有存档文件**：`/sdcard/Android/data/game.taptap.HQGAMES.TapDemons/files/` 下没有 `SaveFile.es3`，这是封号清档留下的状态。

## 四、对本项目的三条结论

1. **无法通过官方服务器获得账号** —— `qingQiu.asp` 已是空壳。想进游戏只能构造本地状态。
2. **黑名单接口已退化**，`heiMingDan.asp` 只要 `qingQiuID` 非空就回 `1`。但它是否还参与清档判断，取决于游戏侧怎么解读这个 `1`（见 `docs/14` 的 `XianShiNiCheng.HeiMingDan()`）。
3. **存档完全本地化** —— 服务器上没有任何存档接口。这反过来印证了 docs/11 的结论：存档只由 `ES3(AES, hqgames@2013)` 外层 + `DES(PJSQJ678)` 内层保护，与账号无关。

### 踩坑记录

- **PowerShell here-string（`@'...'@`）里含单引号会截断脚本** —— `"a'"` 这类 SQL 注入载荷必须写进 `.py` 文件，不能在 `& $py -c @'...'@` 里内联。
- `urllib` 请求该服务器偶发 `TimeoutError`，需要加 3 次重试 + 1 秒退避。
- `urllib.parse.urlencode` 默认就是 urlencoded，正确；用 `multipart/form-data` 会被服务器判 `-1`。
