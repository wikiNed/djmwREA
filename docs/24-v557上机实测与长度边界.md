## 一、本轮解决的两个卡点

### 1.1 「点进入游戏没反应」其实是个假卡点

docs/23 记录旧版卡在「创建信息」界面，按钮亮绿但点不动。实测发现：**按钮早就触发了**，
只是输入法候选栏（横条里显示 `wikinde` + 确定）一直停在屏幕底部，盖住了后续画面，
`adb exec-out` 拉回来的截图始终是「创建信息」那一帧。

**正确操作**：

```powershell
# 输入法弹出后，用 BACK 收键盘并清焦点
adb -s emulator-5558 shell "input keyevent 4"
# 立刻进入开场动画「世界变的浑沌」
adb -s emulator-5558 shell "input tap 360 1200"   # 点击任意处跳过
```

判定输入法是否真的收起：

```powershell
adb -s emulator-5558 shell "dumpsys input_method | grep -o 'mInputShown=[a-z]*'"
# 必须是 mInputShown=false
```

> **教训**：`input keyevent 111`（ESC）会**清空** Unity 输入框内容；
> 而 `input keyevent 4`（BACK）只收键盘、保留内容。昵称输入完成后应直接用 BACK。

### 1.2 实名弹窗：判据是 `accountType`，不是 `saveTimeStamp`

docs/23 §二 写的是「把 `saveTimeStamp` 改成 0」。**该方法在本轮失效**：
游戏启动会把 `saveTimeStamp` 重写回当前时间戳，`chattr +i` 也拦不住（弹窗照旧）。

重新反汇编 `Lcom/antiaddiction/sdk/service/PlayLogService;->checkUserStateByLocal`：

```smali
0018  invoke-virtual {v6}, Lcom/antiaddiction/sdk/bean/User;->getAccountType()I
001c  const/4 v3, #4
001e  if-eq v2, v3, 0060        ; accountType == 4 → 直接免限制
0020  invoke-virtual {v6}, Lcom/antiaddiction/sdk/bean/User;->getAccountType()I
0026  if-gtz v6, 002b           ; accountType <= 0 → 下落判定
0028  const/4 v6, #0
0029  const/4 v4, #3            ; restrictType = 3（未实名受限）
```

**正解**：`/data/data/com.HQGAMES.TopDemons/shared_prefs/USER_INFO<账号>.xml` 里把
`"accountType":0` → `"accountType":4`。改完重启，实名弹窗消失，直接进「创建信息」。

```xml
<string name="testwk01@163.com">{"userId":"testwk01@163.com","identify":"","accountType":4,
"onlineTime":0,"payMonthNum":0,"saveTimeStamp":0,"userName":"","phone":"","birthday":""}</string>
```

## 二、改档生效：钻石 0 → 9999（数值级证据）

存档路径 `/sdcard/Android/data/com.HQGAMES.TopDemons/files/testwk01@163.com`
（**文件名 = 账号名**，75167 字节）。

### 2.1 写入并确认

```powershell
python scripts/v557_pad.py --in wk.save --out wk_r4.save --zhuanshi 9999
# 明文 37573 -> 密文 37576 -> 文件 75167，delta = 0
```

推送后启动，**主界面右上角钻石直接显示 `9999`**（原为 0）。
游戏回写后拉回实测：`ZuanShi = 9999`，文件仍 75167 字节，header 完全未变。

### 2.2 关键结论

`ZuanShi` 从 `0`（1 字符）改成 `9999`（4 字符），**明文变长 3 字节**，
但因为 DES 按 8 字节分块补位，**密文长度没变**（都是 37576），所以文件总长不变（75167），
改档被完整接受。

## 三、宠物加成：战斗力 1 → 3.60 万（首次量化）

### 3.1 三种实验的对照

| 实验 | 存档 | 宠物状态 | 主角「战斗力」 | 结论 |
|---|---|---|---|---|
| 基线 | `wk.save` | 86 只全 `Level 1`、`IsXieDai=0` | **1** | 无宠物加成 |
| 全体升级 | `wk_pet9.save` | 86 只全 `Level 9`、`IsXieDai=0` | **1** | **升级本身不加成** |
| 携带一只 | `wk_carry.save` | 宠物0 `Level 60/JinHua 4/JinJie 9/IsXieDai=1`，其余 85 只仍 1 级 | **3.60 万** | **携带才加成** |

### 3.2 决定性证据

推入 `wk_carry.save` 后主界面显示：

```
左上角总战斗力：43.20万        （原 1）
武器栏　　　　：3.60万         （原 1）
```

角色面板「属性」页：

```
等级：1              血量：1
麒麟臂：3.60万        暴击：0.00%
攻速：取决于手速      魔速：无
躲闪：无              魔闪：无
战斗力：3.60万
```

**主角等级、血量、暴击全部没变，唯一变的是一只携带宠物。**

### 3.3 游戏原样回写（机制性证据）

启动后拉回存档，宠物段 `segs[6]`：

```json
{"ChongWuID": 0, "ChongWuLevel": 60, "ChongWuJinHua": 4, "ChongWuJinJie": 9,
 "ChongWuYongJiu_HP": 0, "ChongWuYongJiu_Damage": 0, "IsXieDai": 1, "IsMaoXian": -1}
```

其余 85 只仍是 `Level 1 / IsXieDai 0`，文件 75167 字节未变。

### 3.4 结论

- **`IsXieDai`（携带标志）才是宠物加成的开关**，只改 `ChongWuLevel` 不加成。
- 一只 `60 级 / 进化 4 / 阶级 9` 的宠物带来 **3.6 万**战斗力。
- `IsMaoXian = -1` 表示已拥有，86 只全部是 `-1`，与 docs/14 的语义一致。

## 四、★ 长度边界：推翻了 docs/23 §四 的结论

### 4.1 实测数据

| 存档 | 文件长度 | 明文长度 | `h[2]` | `h[11]` | 结果 |
|---|---|---|---|---|---|
| `wk.save`（原始） | 75167 | 37570 | `0x99` | `0x90` | ✅ 基线 |
| `wk_r4`（钻石 9999） | 75167 | 37573 | `0x99` | `0x90` | ✅ **成功** |
| `wk_pet9`（宠物 9 级） | 75167 | 37570 | `0x99` | `0x90` | ✅ 成功 |
| `wk_carry`（携带宠物） | 75167 | 37571 | `0x99` | `0x90` | ✅ 成功 |
| `wk_rich`（钻石 9999999） | **75183** | 37576 | `0xb9` | `0xb0` | ❌ **黑屏** |
| `wk_neg2`（压缩 seg8） | **75151** | 37564 | `0x79` | `0x70` | ❌ **黑屏** |

### 4.2 失败时的异常栈（`wk_rich`，delta=+16）

```
EndOfStreamException: Unable to read beyond the end of the stream.
  at System.IO.__Error.EndOfFile ()
  at System.IO.BinaryReader.ReadString ()
  at ES2Reader.Read[T] (ES2Type es2type)
  at ES2.Load[T] (System.String identifier)
  at ShuJuDate.LoadGame ()
  at ChuangJianPlayer.DengLuChengGong ()
  at ChuangJianPlayer+<PanDuanChongXinDengLu>d__25.MoveNext ()
```

### 4.3 结论

**docs/23 §四 的「delta ±102 都合法」不成立。**

本轮 4 个成功案例**文件长度全部是 75167**，2 个失败案例**长度都变了**。
`h[2]` / `h[11]` 的单字节修正并不能让游戏接受变长的存档。

真实约束是 **DES 密文长度必须恒定**（37576 字节）：

```
明文 ≤ 37576 且向下对齐后仍为 37576  →  成功
明文超出 37576 一个块                →  失败（EndOfStreamException）
```

也就是说：**改档必须让「密文分块数」保持不变**，而不是仅仅修正 header。
`ZuanShi 0→9999` 能过，是因为 37570→37573 仍在同一个 8 字节块内；
`ZuanShi 0→9999999`（37570→37576）**恰好跨块**，就失败了。

> 这也解释了 docs/23 §6.1 里那几个 delta=±16/±32 的「成功」案例：
> 它们当时用的判定脚本只匹配 `CryptographicException` / `FormatException`，
> **没有匹配 `EndOfStreamException`**，很可能把黑屏误判为成功。

### 4.4 `v557_pad.py` 的 header 计算 bug（已标注）

`read_segments()` 返回的 header 已经带长度偏移，脚本又按 `BASE_TOTAL` 叠加一次，
导致 `wk_rich` 的 `h[2]` 被算成 `0xb9`（+32）而不是正确的 `0xa9`（+16）。
已在函数 docstring 里写清约束。

## 六、新增工具

### `scripts/v557_pad.py`

在 docs/23 `v557_fit.py` 基础上重写的编辑器，支持：

```
--pets-level N    所有宠物等级
--zhuanshi N      钻石
--drop N          压缩 seg8 的 1000000000.0 哨兵（每个省 13 字节）
--dry-run         不写盘
```

内部用 `separators=(",", ":")` 紧凑序列化，与游戏原生排版一致。

### `scripts/v557_carry.py`

宠物「携带」实验专用：

```
--carry-id N      指定宠物设为 IsXieDai=1
--all             所有宠物都设为携带
--level / --jin-hua / --jin-jie   同时设置等级/进化/阶级
```

### `meta_v557.py` / `meta_types.py`（v27 metadata 解析）

`docs/23` 只用了 dex 与 ARM 反汇编，没有 metadata 解析器。本轮补上：

```powershell
python meta_v557.py header                  # 各段偏移/长度/结束位置
python meta_v557.py find <关键词>            # 在 string 表里搜
python meta_types.py types <关键词>          # 按类型名搜索
python meta_types.py class <类型名>          # 列出该类所有方法
```

**v27 的关键结构常量（与常见文档不符，实测确定）：**

| 结构 | 步长 | 验证方式 |
|---|---|---|
| `Il2CppTypeDefinition` | **`0x58`**（88 B） | 0x58 前 20 条读出 19 个合法类型名；0x5C 只有 11 个且出现 `'d'`/`'ore'` 碎片 |
| `Il2CppMethodDefinition` | **`0x20`**（32 B） | 0x20 前 20 条 20/20 合法；0x2C 只有 14/20 |

v27 头部是「每段长度」而非绝对偏移，从 `8 + 4*字段数` 起逐段累加。
**自检：最后一段结束游标 `0x38e390` = 3728272 = 文件大小，零偏差。**

关键段（`global-metadata_v557.dat`，3728272 B）：

```

string               0x47a00   595708

typeDefinitions      0x2fcd90  426096   (4842 条，/0x58)
images               0x364e00     1960   (49 条，/0x28)
```

`ChuangJianPlayer` = 类型 **#4395**，17 个方法：

### 踩坑

- **`Set-Content -Encoding UTF8` 会把中文写成 GBK 乱码**，导致 `SyntaxError: unterminated string literal`。
  改文件用 `edit` / `write` 工具，不要用 PowerShell 重写含中文的文件。
- PowerShell here-string 传给 `python -c` 会吃掉引号；`b'$'.join()` 里的 `$` 会变成空。
  **一律写 `.py` 文件再执行。**
- `ldconsole list2` 是 GBK，需 `[System.Text.Encoding]::GetEncoding(936)` 解码。
- 截图必须 `screencap -p /sdcard/x.png` + `pull`；`exec-out` 重定向会被 PowerShell 破坏。

## 八、一句话总结

**v5.5.7 改档真正可用的范围比 docs/23 认为的窄得多：
必须保持 DES 密文分块数不变（本例恒为 37576 字节 / 文件 75167），
在这个前提下钻石、宠物等级、宠物携带都能改，且游戏会原样回写；
宠物加成的开关是 `IsXieDai` 而非 `ChongWuLevel`，
携带一只 60 级进化 4 阶级 9 的宠物可把战斗力从 1 拉到 3.60 万。**
