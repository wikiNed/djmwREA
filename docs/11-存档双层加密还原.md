> 结论先行：`saves/*.es3` **不是单层 ES3 加密**，而是

## 2. 三个易踩的坑

### 坑 1：ES3 桶明文缺最外层 `{` 和第一个 key 的开引号

实测解出的前 40 字节：

```
6f 37 34 4a 55 6b 68 39 6a 77 3d 3d 22 20 3a 20 7b 0a 09 09 ...
 o  7  4  J  U  k  h  9  j  w  =  =  "     :     {  \n \t \t
```

即 `o74JUkh9jw==" : {`。**这是 ES3 写入器的正常输出，不是解密失败的残片。**
错误的修补方式：

- 补 `'{"'` → 变成 `{"o74J...`，但原文本里 key 后面已有 `"`，得到 `{"o74J""` →
  `json.decoder.JSONDecodeError: Expecting ':' delimiter: line 1 column 4 (char 3)`
- 只补 `'{'` → 得到 `{o74J...`（缺开引号）→ 同样是 `Expecting ':' delimiter`

正确做法按首字符分三支：

```python
if s.startswith("{"):        s2 = s
elif s.startswith('"'):      s2 = '{"' + s[1:]   # 首项自带引号
else:                        s2 = '{"' + s
```

### 坑 2：重建桶时 key 后必须跟一个 `"`

正确的头行模板：

```python
head = '%s" : {\n\t\t"__type" : "string",\n\t\t"value" : "%s"\n\t}' % (newkey, hexstr)
```

漏掉 `%s` 后面的 `"` → 桶变成 `{o74JUkh9jw== : {...}` →
`Invalid control character at: line 1 column 19 (char 18)`。

### 坑 3：内层 DES 尾填充不是标准 PKCS7

明文 38144 字节，末尾是 `...}\x04\x04\x04\x04`——
块长 8 却只填 4 个字节。所以解密后**不能**用 `unpad()`，
应扫描尾部连续相同字节，`1 <= n <= 8` 才剥离，否则退回 `rstrip(b"\x00")`。
加密方向按 NUL 补到 8 的整数倍即可（游戏读回时会容忍）。

## 3. 使用方式

`.es3` 已经对 `savedit.py` 完全透明，无需先手动 unpack：

```powershell
# 直接改 .es3（内部自动两层解码 + 两层封回）
python scripts\savedit.py currency saves\SaveFile_orig.es3 --zuanshi 888888
python scripts\savedit.py get      saves\SaveFile_orig.es3 13.ZuanShi
python scripts\savedit.py roundtrip saves\SaveFile_orig.es3
```

也可显式控制两层：

```powershell
python scripts\es3save.py unpack saves\SaveFile_orig.es3 saves\plain.json
python scripts\es3save.py pack   saves\plain.json      saves\out.es3
python scripts\es3save.py verify saves\out.es3
```

`pack` 后会自动 `read_save` 回读校验并打印「回读校验: 一致」。
