## 二、`new_save.py` —— 从零构造

### 2.1 为什么可行

`docs/20` 已证明：ES3 桶里 string 槽的名字 = `PlayerData.GetID()` =
`ShuJuDate.playerZhangHao` = `PlayerPrefs["UJHJKOikhS"]` = 账号名。
**没有哈希，没有随机数**，所以账号名一确定，槽名就确定。

### 2.2 三份输入

| 输入 | 来源 | 作用 |
|---|---|---|
| 14 段骨架 | `evidence/templates/playerDate_03.bin`（104886 字节） | 官方满级档，14 段齐全，字段/类型/顺序天然合法 |
| salt / iv / `_Key` | 一份真机原档（自动在 `work/live`、`evidence/saves` 里找） | `docs/19` 要求必须复用，否则黑屏 |
| 账号名 | `--account` | 决定桶里 string 槽的名字 |

### 2.3 硬约束：不给原档就拒绝运行

没有原档时 salt/iv 只能随机，而 `docs/19` 记录的反例正是「换 salt/iv → 黑屏」。
所以脚本**默认拒绝**，必须显式 `--allow-random-outer` 才继续，并在 stderr 打警告。
不默默生成一个可能读不出的文件。

## 三、`edit_seg2510.py` —— seg2/5/10 编辑器

### 3.1 核心设计：上限从模板现读，不写死

第一版把 `HOME_LEVEL_MAX` 猜成 5、魔窟难度猜成 10，结果：

```
MoKuNanDuDangQian 20 -> 10      ← 把玩家的进度改小了
JiaYuanLevel      240 -> 5      ← 差了两个数量级
```

**三份官方模板才是上限的可靠上界**：

| 字段 | playerDate_01 (36级) | playerDate_02 (56级) | playerDate_03 (60级) |
|---|---|---|---|
| `JiaYuanLevel` | 68 | 68 | **240** |
| `FaMuChangLevel` | 67 | 92 | **299** |
| `KuangShiChangLevel` | 67 | 76 | **245** |
| `MuCaiShuLiang_LiXianKu` | 538680 | 354400 | **5364060** |
| `KuangShiShuLiang_LiXianKu` | 538680 | 238523 | **3601500** |
| `MoGaoLevel` | 1 | 7 | **200** |
| `MoShiShuLiang` | 0 | 90 | **10000** |
| `MoKuNanDuDangQian` | 1 | 2 | **20** |
| `MoKuNanDuBest` | 1 | 3 | **26** |
| `DaoZeiYaoShi` | 60 | 72 | **4** ← 注意 |

现在 `template_max(seg, field)` 逐字段取三份模板的 max，`--list --show-limits`
可以直接看：

```
MoGaoLevel                       1   [模板上限 200]
MoShiShuLiang                    0   [模板上限 10000]
MoKuNanDuDangQian                1   [模板上限 20]
MoKuNanDuBest                    1   [模板上限 26]
```

### 3.2 反直觉发现：等级越高，钥匙越少

`DaoZeiYaoShi`：36 级 60 → 56 级 72 → **60 级 4**。

这不是笔误，是**消耗后的剩余存量**（60 级玩家把钥匙花光了）。所以对这类
「存量型」字段用模板 max 当上限是错的 —— 代码里改成 `max(cap, 60) * 10`，
并在注释里写明理由。

**教训**：不是所有字段都能把「模板里的值」当上限。要看它代表**存量**还是
**产能/等级**。等级/人口/难度是单调的，存量不是。

### 3.4 离线收益的坑

`seg2` 的 `*_LiXianKu` 是**离线收益库**，不受 UI 库存上限约束
（顶端资源栏显示 `MuCaiShuLiang/1500`，那才是主库存）。
想刷木材/矿石，改 `*_LiXianKu` 比改 `MuCaiShuLiang` 隐蔽得多。

再配合 `ZiYuanLiXianTime = 0`：下次进游戏时离线时长 = 当前时间戳，
按满级产能结算一笔巨大的离线收益，而 UI 上看不出任何字段被改过。
